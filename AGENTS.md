# AGENTS.md

## Purpose

- Black-box system, multi-tenant and load tests for Project Continuum, written for Grafana k6. They run against a live stack (docker-compose or a cluster) and never import platform code.

## Ownership

- `docker/`: the stack under test. `docker-compose.yml` is a copy of `continuum-feature-template/docker/docker-compose.yml` with one change: the four platform images (api-server, orchestration-service, message-bridge, credentials-server) use `${CONTINUUM_PLATFORM_VERSION:-0.0.21}`. `postgres/`, `temporal/` and `mosquitto/` are copies of the config next to it.
- `lib/`: helpers shared by every suite (`config`, `tenant`, `workflows`, `capabilities`, `metrics`, and the pure `util.js`).
- `suites/`: k6 scripts. `smoke.js` and `tenancy/isolation.js` exist today.
- `fixtures/workflows/`: workflow models posted to the api-server.
- `test/`: `node --test` unit tests for `lib/util.js`.

## Local Contracts

- A tenant is only the `x-continuum-user-id` header. Make every request through `lib/tenant.js` so it carries the header and the `tenant:<id>` metric tag.
- Tenant ids and workflow names are prefixed `systest-<runId>` / `/systest/<runId>/`. Workflow runs cannot be deleted through the API, so this prefix is the only way to find test data afterwards.
- Base URLs come from env vars in `lib/config.js` (`API_SERVER_URL`, `CREDENTIALS_URL`, ...). Never hardcode a port: the api-server is 8080 in compose and 8081 in the IntelliJ run configs.
- Isolation checks are hard failures: tenant B must get 404 (or an empty list) for anything tenant A owns. `isolation_violations` must stay 0.
- Keep k6-specific code (`k6/http`, `k6/metrics`, `open()`) out of `lib/util.js`, which must stay unit-testable with plain node.
- `docker/.env` pins the Postgres and Temporal image versions. It is copied from the template repo and is not read or generated by tooling here.
- Tests that need an optional feature worker must check `lib/capabilities.js` first and skip, not fail, when the nodes are absent.
- Load profiles must stay opt-in and must not run against a shared environment by accident.

## Work Guidance

- When the template compose changes, copy it over again and re-apply the `CONTINUUM_PLATFORM_VERSION` substitution on the four platform images; make no other hand edits to `docker/docker-compose.yml`.
- Test another platform release with `CONTINUUM_PLATFORM_VERSION=0.0.22 make up`. Set it before every `make` target that touches the stack, or compose falls back to the default and recreates containers on the old version.
- Assert status codes and the fields the suites rely on, not whole response bodies.
- The `temporalStatus` field of `/status` may arrive as a name or an ordinal; always go through `normalizeStatus`.
- A 404 or 500 from `/status` right after a start can be Temporal visibility lag; poll, do not fail on the first miss.

## Verification

- `npm test` (unit tests for `lib/util.js`) and `npm run check` (syntax check of every script). Both need only node.
- `make up && make smoke && make tenancy` against a clean compose stack. Needs Docker and k6.
